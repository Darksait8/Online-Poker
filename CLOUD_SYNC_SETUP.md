# Настройка облачной синхронизации пользователей

Эта система позволяет автоматически синхронизировать данные пользователей между всеми серверами без необходимости ручного обновления через GitHub.

## Как это работает

1. **Сервер синхронизации** - централизованное хранилище данных пользователей (можно запустить на любом хостинге)
2. **Локальные серверы** - автоматически синхронизируются с сервером синхронизации при каждом изменении
3. **Автоматическая синхронизация** - при регистрации, входе или обновлении профиля данные автоматически отправляются в облако

## Вариант 1: Использование отдельного сервера синхронизации (Рекомендуется)

### Шаг 1: Запустите сервер синхронизации

Сервер синхронизации можно запустить на любом доступном сервере (ваш ПК, VPS, облачный хостинг).

```bash
cd Server/SyncServer
dotnet run -- --port 8889 --key "ваш-секретный-ключ"
```

**Важно:** Используйте `--` после `dotnet run`, чтобы передать аргументы программе, а не dotnet CLI.

Или с переменными окружения:
```bash
export SYNC_PORT=8889
export SYNC_DATA_FILE="sync_users.json"
export SYNC_API_KEY="ваш-секретный-ключ"
dotnet run
```

### Шаг 2: Настройте локальные серверы

На каждом устройстве, где запущен игровой сервер, установите переменные окружения:

**Windows (PowerShell):**
```powershell
$env:POKER_SYNC_URL="http://ваш-сервер:8889"
$env:POKER_SYNC_API_KEY="ваш-секретный-ключ"
```

**Windows (CMD):**
```cmd
set POKER_SYNC_URL=http://ваш-сервер:8889
set POKER_SYNC_API_KEY=ваш-секретный-ключ
```

**Linux/Mac:**
```bash
export POKER_SYNC_URL="http://ваш-сервер:8889"
export POKER_SYNC_API_KEY="ваш-секретный-ключ"
```

### Шаг 3: Запустите игровой сервер с синхронизацией

```bash
cd Server
dotnet run --sync-env
```

Или напрямую указать URL:
```bash
dotnet run --sync http://ваш-сервер:8889
```

## Вариант 2: Использование облачного хранилища

Если у вас есть доступ к облачному API (например, Google Drive, Dropbox), можно настроить `CloudSyncService` для работы с ним.

## Преимущества

✅ **Автоматическая синхронизация** - не нужно вручную обновлять файлы
✅ **Доступность** - пользователи видят свои аккаунты на всех устройствах
✅ **Масштабируемость** - работает с любым количеством пользователей
✅ **Надежность** - данные хранятся централизованно

## Безопасность

⚠️ **Важно**: Измените API ключ по умолчанию!

```bash
# Генерируйте безопасный ключ
openssl rand -hex 32
```

Или используйте переменную окружения:
```bash
export SYNC_API_KEY="ваш-безопасный-ключ-32-символа"
```

## Развертывание на хостинге

### Пример для VPS (Ubuntu/Debian)

1. Установите .NET 8.0
2. Скопируйте файлы сервера синхронизации
3. Создайте systemd service:

```ini
[Unit]
Description=Poker Sync Server
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/path/to/Server/SyncServer
ExecStart=/usr/bin/dotnet run --port 8889 --key "your-secure-key"
Restart=always

[Install]
WantedBy=multi-user.target
```

4. Запустите сервис:
```bash
sudo systemctl enable poker-sync
sudo systemctl start poker-sync
```

### Пример для Windows Service

Используйте NSSM (Non-Sucking Service Manager) или создайте Windows Service.

## Проверка работы

1. Запустите сервер синхронизации
2. Запустите игровой сервер с синхронизацией
3. Зарегистрируйте пользователя на одном устройстве
4. Проверьте, что пользователь появился на другом устройстве

## Устранение неполадок

### Сервер синхронизации не запускается

- Проверьте, что порт не занят: `netstat -an | grep 8889`
- Убедитесь, что у вас есть права на прослушивание порта
- Проверьте файрвол

### Синхронизация не работает

- Проверьте переменные окружения: `echo $POKER_SYNC_URL`
- Проверьте доступность сервера: `curl http://ваш-сервер:8889/users`
- Проверьте API ключ
- Посмотрите логи сервера синхронизации

### Данные не синхронизируются

- Убедитесь, что сервер синхронизации запущен
- Проверьте сетевую связность
- Проверьте логи игрового сервера на наличие ошибок синхронизации

## Альтернативные решения

Если не хотите запускать отдельный сервер, можно использовать:
- **GitHub Gist API** - бесплатно, но с ограничениями
- **Google Drive API** - требует настройки OAuth
- **Dropbox API** - требует настройки OAuth
- **Собственный хостинг** - полный контроль

## Резервное копирование

Сервер синхронизации автоматически сохраняет данные в файл `sync_users.json`. Регулярно делайте резервные копии этого файла!
