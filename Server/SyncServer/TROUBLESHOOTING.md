# Устранение проблем с сервером синхронизации

## Ошибка "Отказано в доступе"

### Причина
HttpListener в Windows требует специальных прав для прослушивания портов.

### Решение 1: Использование другого порта

Попробуйте использовать порт выше 1024 (например, 9000):

```bash
dotnet run -- --port 9000 --key "piska"
```

### Решение 2: Резервация URL (требует прав администратора)

Откройте PowerShell или CMD **от имени администратора**:

```powershell
netsh http add urlacl url=http://localhost:8889/ user=Everyone
```

Или для конкретного пользователя:
```powershell
netsh http add urlacl url=http://localhost:8889/ user=%USERNAME%
```

### Решение 3: Запуск от имени администратора

Просто запустите командную строку или PowerShell от имени администратора и выполните:

```bash
cd Server\SyncServer
dotnet run -- --port 8889 --key "piska"
```

### Решение 4: Проверка занятости порта

Проверьте, не занят ли порт другим приложением:

**Windows:**
```cmd
netstat -ano | findstr :8889
```

Если порт занят, либо остановите приложение, либо используйте другой порт.

## Проверка работы

После успешного запуска вы должны увидеть:
```
🌐 Сервер синхронизации запущен на порту 8889
📁 Файл данных: sync_users.json
🔑 API Key: piska
📍 Доступен по адресу: http://localhost:8889/
Ожидание запросов...
```

## Тестирование

Откройте браузер и перейдите по адресу:
```
http://localhost:8889/users
```

Или используйте curl:
```bash
curl http://localhost:8889/users
```

**Важно:** Не забудьте добавить заголовок `X-API-Key` при реальных запросах!
